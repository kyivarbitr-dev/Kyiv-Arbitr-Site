# Мапа лотів Prozorro.Продажі (Україна, області + м. Київ)

Сторінка `prozorro-map.html` показує на мапі України активні лоти Prozorro.Продажі.

- Лоти розкладено за областями. **Місто Київ — окремий регіон** і стоїть першим у списку, Київська область іде окремо.
- Близькі точки групуються в кружки з числом. При наближенні вони розкриваються.
- Фільтри: регіон, пошук, «лише банкрутство».
- Можна дати пряме посилання на регіон, наприклад `prozorro-map.html?region=м. Київ` або `prozorro-map.html?region=Львівська`.

Дані оновлюються щодня через GitHub Actions. Після оновлення Netlify сам перевидає сайт.

## Файли в репозиторії Kyiv-Arbitr-Site

Нові файли:
```
prozorro-map.html                    ← сторінка мапи (адреса kyivarbitr.com.ua/prozorro-map)
js/prozorro-map.js                   ← логіка мапи
.github/workflows/prozorro-map.yml   ← щоденне завдання (06:10 за Києвом влітку)
scripts/prozorro_ua.py               ← збір лотів, визначення області, геокодування
data/prozorro-ua.geojson             ← дані для мапи (спершу порожні)
data/prozorro-summary.json           ← коротка статистика для анонсу в «Аналітиці»
```

Змінені файли (замінити наявні):
```
analytics.html      ← вкладки «Матеріали / Мапа» і анонс мапи з живими цифрами
en/analytics.html   ← картка з посиланням на мапу
links.html          ← мапа першим пунктом у блоці Prozorro.Sale
lot-check.html      ← посилання на мапу
css/style.css       ← стилі мапи й вкладок (додано в кінець файлу)
sitemap.xml         ← додано /prozorro-map; дату оновлює скрипт щодня
netlify.toml        ← короткий кеш для /data/*, службові файли закрито
```

Папка `.github` починається з крапки. У веб-інтерфейсі GitHub створіть файл через **Add file → Create new file** і впишіть шлях `.github/workflows/prozorro-map.yml`, потім вставте вміст файлу.

## Як знайти мапу в Google і Bing

На сторінці вже є: окрема адреса, заголовок і опис під пошукові запити, канонічне посилання, розмітка schema.org (WebPage, хлібні крихти, Dataset), картка для соцмереж, запис у sitemap.xml і внутрішні посилання з «Аналітики», «Корисних посилань» і «Перевірки лотів».

Після публікації:
1. **Google Search Console** → «Перевірка URL» → `https://kyivarbitr.com.ua/prozorro-map` → **Надіслати запит на індексування**.
2. Там само: **Файли Sitemap** → повторно надішліть `sitemap.xml`.
3. **Bing Webmaster Tools** → **URL Submission** → та сама адреса (Bing передає дані й до DuckDuckGo та Yahoo).
4. Поділіться посиланням у Google Business Profile і соцмережах: зовнішні посилання пришвидшують індексацію.

Строки появи в пошуку від Google не залежать і заздалегідь невідомі [уточнити в Search Console через кілька днів].

## Перший запуск

1. **Settings → Actions → General → Workflow permissions** → **Read and write permissions** → Save.
2. **Actions → «Мапа Prozorro (Україна)» → Run workflow**.
   - Перший запуск переглядає зміни за 120 днів по всій країні і може тривати від 30 хвилин до 2 годин.
   - Щоденні запуски потім тривають кілька хвилин плюс час на геокодування нових адрес.
3. Після завершення Netlify перевидасть сайт.

## Як визначається місце на мапі

Порядок спроб:

1. Координати, які вказав продавець.
2. Точна адреса (вулиця й будинок) через OpenStreetMap Nominatim.
3. Центр населеного пункту.
4. Центр області.

Якщо точку поставлено приблизно, у спливаючому вікні є про це примітка.

Nominatim дозволяє не більше 1 запиту на секунду. Тому за один запуск обробляється обмежена кількість нових адрес, а результати кешуються в `data/geocache.json`. Точність мапи зростає з кожним днем. Лоти, у яких не визначився навіть регіон, показуються списком під мапою.

## Налаштування

Параметри задаються змінними середовища в кроці `run` у workflow:

| Змінна | За замовч. | Що робить |
|---|---|---|
| `FIRST_RUN_DAYS` | 120 | глибина першого сканування, у днях |
| `MAX_GEOCODE_ADDR` | 800 | скільки нових точних адрес геокодувати за запуск |
| `MAX_GEOCODE_PLACE` | 600 | скільки нових населених пунктів геокодувати за запуск |

Якщо репозиторій **приватний**, хвилини GitHub Actions лімітовані безкоштовним планом. Тоді `MAX_GEOCODE_ADDR` варто зменшити до 300–400. Для публічних репозиторіїв обмежень на стандартних машинах немає [уточнити актуальні умови GitHub].

## Що перевірити після першого запуску [уточнити]

API Prozorro.Sale з робочого середовища, де готувався код, був недоступний. Скрипт написано за офіційним описом відкритих даних і з запасом на різні назви полів. Після першого запуску перевірте:

- **Посилання на лот.** Якщо формат сторінки лота інший, змініть `LOT_URL` у `scripts/prozorro_ua.py`.
- **Регіони.** У журналі запуску в кінці є кількість лотів по кожному регіону. Якщо «Регіон не визначено» помітно більший за інші, надішліть журнал, і правила розпізнавання буде доналаштовано.
- **Банкрутство.** Лот вважається банкрутним, якщо `sellingMethod` містить «bankrupt». Перевірте на відомому вам лоті.

## Обмеження

- Адреси в лотах продавці заповнюють вручну, тому частина буде з помилками. Типовий приклад: «Київська обл., м. Київ». Такі лоти скрипт відносить до міста Києва.
- Відкриті дані Prozorro.Продажі можна вільно використовувати за умови посилання на джерело. Посилання вже є на сторінці.
